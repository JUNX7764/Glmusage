# GLMUsage 用量洞察迭代 PRD

- 方案版本：**v0.3 · 已确认进入隔离开发**
- 日期：2026-11-06
- 当前源码基线：`main` / `b0a32a8` / `v1.0.23`
- 范围：GLMUsage；KimiUsage 为用户误输入，不在本轮范围内
- 用户已授权：创建新 session，在独立 worktree＋分支实现并由主会话审核。
- 开发边界：不提交、不推送、不合并、不发布、不部署、不停止或替换运行中的应用、不真实用卡；真实凭据网络验证须遵守工程文档的独立验收边界。

## 1. 本版结论

**额度／套餐到期、峰谷、重置卡三块保持原样；优化头部与下半部用量展示。**

学习 CodexUsage 的周期展开、每日趋势、悬停取值和两项比较；保留 GLM 自己的数据列、峰谷规则、重置卡与 MCP。没有 Tibo，不创建替代动态灯，不增加未经证实的历史累计。

面板只显示必要标题、数字、单位与操作，不常驻技术口径、开发状态或解释性脚注。这些内容写在 PRD 内，不塞进用户界面。

## 2. 冻结区域：完全不改

以用户提供的当前截图为视觉与交互基准，以下三块不属于本次设计调整范围。

| 冻结区域 | 必须保留 |
|---|---|
| 额度与套餐到期 | 5 小时／7 天行、百分比、进度条、剩余／总 credits、右侧重置时间、套餐到期；布局、字体、颜色、文案与逻辑保持 |
| 峰谷状态 | 整张卡的位置、尺寸风格、图标、现有 Emoji、状态文案、下次高峰与活动判断保持；不压缩成行 |
| 重置卡 | 整张卡、标题、使用按钮、每张卡到期列表、暂无可用状态、选择与二次确认流程保持；不替换成数量摘要 |

菜单栏双行额度、底部版本号与检查更新、原位更新进度、立即刷新、开机自启和退出保持。

### 2.1 头部最新确认（唯一放开的上半部调整）

参考用户提供的 Codex 头部：沿用 GLM 自己的应用图标，右侧第一行为「GLM 用量」＋独立套餐 badge，第二行可选显示当前 GLM 账号邮箱。套餐标签同样式、仅名称变化，不按套餐设计不同图标；名称来自现有有效订阅，不硬编码 PLUS/PRO，也不根据名称修改额度能力。

邮箱仅当现有授权范围内能可靠确定为当前 GLM 账号时展示；未知／不匹配／解析失败则整行隐藏，不填演示邮箱、不拿 ZCode 账号邮箱当 GLM 邮箱、不新增个人资料网络查询、不记录邮箱到 status.json。长名称与邮箱须可截断，不挤压 badge；无邮箱时不保留空白高度。套餐到期仍放冻结区原位置，不移到头部。

主原型图尚为旧标题「GLM 余额（Pro 套餐）」，头部以本节最新确认及 `docs/design/glmusage-header-reference.png` 为准，其余以单行比较条图为准。

**冻结不等于锁定截图里的数据。** 实际额度、套餐、卡片日期继续取真实响应；原型仅用截图数值表示现有外观，不作为套餐定价规格。

旧原型 `glmusage-next-prototype.html` 因重排冻结区域已撤回，不用于本轮开发或评审。以本版原型和本 PRD 为准。

### 明确不要的界面内容

正常界面中不出现以下说明，也不以类似措辞重新加回：

- 数据来自哪个监控接口、与 credits 如何区分的脚注。
- 截至昨日／归日时区／接口接入待验证等技术或开发说明。
- 没有全历史数据、不能用近 30 天冒充累计等解释。
- 「统计口径」按钮、信息图标、面向开发的待验证占位。

这些规则只删除冗余说明，**不删除必要的异常反馈**：加载时 `--`、失败时「暂不可用」、缺数时「数据不足」仍要保留。

## 5. 用量情况

### 5.1 标题与数据列

- 标题固定「用量情况」，去掉原标题括号说明。
- 保留今日／近 7 天／近 30 天三行。
- 列为「周期 / Token / 调用次数」。
- GLM 当前模型明细只提供模型 Token；**不添加输入／输出列，不伪造模型调用次数**。
- 模型名称直接来自响应，不硬编码原型中的示例模型。

### 5.2 展开行为

- 保留整节展开／收起。
- 点击某个周期行，展开／收起该周期模型 Token。
- 多个周期可以同时展开。
- 刷新、数据重绘后保留展开状态与滚动位置。
- 没有模型明细的周期不显示可点击展开箭头；不能展开一个空列表。
- 模型汇总不全时不强行调整数字配平，不补造「其他」或未知值。

## 6. 每日用量

### 6.1 默认外观

- 放在「用量情况」下、「MCP 工具」上。
- 标题「每日用量」，右侧仅「近 30 天」。
- 一行显示所选日期和 Token 数；默认选中最新有记录的完整日。
- 下方为 30 日小柱状图，使用现有绿色体系；零值用基线，缺失日用缺口。
- 图下保留少量日期刻度与两项比较，无额外解释性文字。
- 两项比较参考用户图片，采用**单行浅底圆角条＋中间竖分隔线**：左右各占一半，每组「标签＋数值」靠近并整体居中，数值 12pt 半粗体；不再分成上下两行，不通过加高面板解决可读性。比较条高约 30pt，替换原有比较区；其余区域不改。缺数文案也留在对应半区，不串组。仅参考比较条的分组方式，不照抄图片中的累计、橙色主题或说明脚注。
- 增减幅度中性展示，不暗示增用量一定是坏事。

### 6.2 交互

- 鼠标移到哪一天，日期和 Token 数立即切换，不需要点击。
- 命中区域覆盖整天宽度，不只命中柱身；零值日也能读取。
- 离开图表保留最后选中值，避免不断跳回末日。
- 支持键盘左右切换日期、触控选择；提供日期与数值的无障碍标签。
- 悬停、点击、展开不发新网络请求。

### 6.3 比较定义（实现规则，不作为常驻 UI 脚注）

为了不拿半天与整天误比，使用最新完整自然日 D：

- **较昨日**：D 对比 D−1。
- **较前 7 天**：截至 D 的 7 个完整日，对比再前 7 个完整日。
- 百分比为 `(当前 − 基期) / 基期 × 100%`，保留一位小数。
- 双方都为 0：显示「持平」。
- 基期 0、当前大于 0：显示「新增 N」，不显示 Infinity。
- 任一必要日缺失：显示「数据不足」。
- 两个标签始终保留，不因数据不足隐藏整行。

每日图使用完整自然日，现有周期表仍保留当前今日／滚动 7 天／滚动 30 天含义，不为了让两个区域总和相等而改动既有统计。

## 7. GLM 与 Codex 的迁移边界

| 可沿用的大逻辑 | GLM 必须按自身能力处理 |
|---|---|
| 周期行展开模型、多周期同开、刷新保持 | 总 Token＋调用次数＋模型 Token；没有现成输入／输出拆分 |
| 每日图悬停即读数、两项比较 | GLM 每日明细接口能力尚未验证，不套用 Codex 的日桶字段 |
| 保留专属能力与现有操作 | GLM 的峰谷／重置卡／MCP 原样保留，没有 Tibo |
| 不混算不同指标与来源 | credits 是额度，Token 是使用量，MCP 是次数；规则在数据层落实，不做正常界面脚注 |
| 累计必须有可信来源 | 当前没有可靠 lifetime 来源，本版不显示累计 |
| 节制的原生视觉 | 新增区域使用 SF Symbols；冻结区域图标、Emoji 不动 |

MCP 的「工具」是网络搜索、网页读取，不是 Codex／Proma／Hermes 等客户端 Token 分布。本轮不另做 harness 适配。

## 8. 数据前置验证（仅记录于 PRD）

### 8.1 已由当前源码确认

- `GlmUsage.swift:493-505`：窗口总 Token=`totalUsage.totalTokensUsage`、调用数=`totalModelCallCount`、模型=`modelSummaryList[].modelName/totalTokens`。
- `GlmUsage.swift:1571-1598`：今日按系统本地自然日；近 7／30 天按滚动秒数查询。
- `GlmUsage.swift:2262-2330`：冻结的额度／峰谷／重置卡实现。
- `GlmUsage.swift:2332-2406`：现有周期模型展开与 MCP。
- `GlmUsage.swift:2408-2471`：现有头尾、版本、操作与面板尺寸。

### 8.2 开发前需要验证

- 30 天响应中有无可用的小时／日记录，字段、缺失和零值含义。
- 可查跨度、历史保留、分页限制和日期边界。
- 服务端归日时区、数据延迟与历史修订方式。
- 模型汇总的范围是否与窗口总量一致。

本次未读取 GLM 凭据、未调用真实监控接口。原型只表示目标体验，不证明接口已经具备每日数据。日桶来源和时区由开发报告记录，正常面板不展示「待验证」说明。

### 8.3 数据方案

1. 优先复用现有 30 天慢刷新响应的小时／日桶，聚合每日图。
2. 不每 5 分钟新增 30 个单日请求，不从滑动总量差分猜造每日历史。
3. 若没有可用日数据，先不发布每日图：显示简短「暂不可用」，两个比较显示「数据不足」；不展示开发原因、不补零。
4. 如确需逐日回填，另行评审请求预算、并发、缓存与修订策略，不暗中扩大本版。
5. 全历史累计没有可信来源时不显示，也没有「累计暂不支持」之类的占位。

## 9. 异常与现有安全约束

新增用量区域：

- 首次加载显示 `--`，而不是 0。
- 已有旧值可保留，必要时显示简短「待更新」；不堆接口路径或英文错误。
- 某周期失败不清空其他周期；每日图失败不清空用量情况。
- 缺失日不能当零日；缺失比较显示「数据不足」。

冻结区域与更新链路：

- 按现有行为保留，不借异常整理之名改变文案、布局或策略。
- 用卡依旧用户点击＋二次确认，绝不自动执行；未知结果复用同类型幂等 key，成功后约 3 秒补刷，不乐观写 100%。
- 预览不读凭据、不发请求、不消费卡。本版原型不重画用卡确认流程。
- 版本与原位更新继续使用现有逻辑，关闭面板不打断更新；不新增独立更新窗口。

## 10. 性能要求

- 额度 10 秒、慢项 5 分钟的刷新节奏不变。
- 图表只消费慢项数据与缓存，不进入额度高频链路、不新增定时器。
- 悬停／展开／重开直接读内存，不重复解析整个历史、不发请求。
- 只保留需要的日桶与有限修订窗口，数据处理不阻塞主线程。
- 切换账号不串数据；不将凭据写入缓存或诊断。
- 提交开发前后相同条件下的 CPU、内存、wakeups、请求数与展开／重开延迟对比，不预先捏造能耗百分比。

1. **当前：用户已确认方案并授权新 session 开发；头部增加第 2.1 节要求。**
