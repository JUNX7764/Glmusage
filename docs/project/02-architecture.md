# GlmUsage 当前架构概览

> 状态：当前架构摘要。最后核对：2026-11-13。
> 本文解释模块与边界，函数级行为以源码和测试为准。

## 1. 应用形态

GlmUsage 是 macOS 13+、Apple Silicon 的原生 AppKit 菜单栏应用，无 Swift Package 依赖。面板使用原生 `NSPopover`。`GlmUsage.swift` 保留应用入口、数据层与面板组装；`PanelCustomization.swift` 管理面板卡片布局模型与设置视图，周额度周期回顾按职责位于 `Sources/GLMQuotaCycle*.swift`。

应用身份保持为：

- 仓库：`JUNX7764/Glmusage`
- Bundle / LaunchAgent：`com.local.glm-usage`
- 应用：`GlmUsage.app`

## 2. 模块边界

| 模块 | 当前职责 |
|---|---|
| `CredStore` | 读取用户提供的套餐 API Key 或旧版 ZCode 登录凭据，区分凭据来源 |
| `Fetcher` | 智谱额度、模型、工具、订阅和 ZCode 重置卡请求 |
| `GLMStartPlanUsage` | 只读 ZCode 请求用量表，将赠送用量按周期、模型和自然日补入现有统计 |
| `Peak` | 高峰、非高峰和限时活动的本地时段计算 |
| `UpdateChecker` | 检查 GitHub Release 和更新资产，保留同一版本的更新说明 |
| `UpdateProgressController` | 后台更新、进度恢复和错误展示 |
| `GLMPanelLayout` | 面板内容卡片的显隐与顺序模型，负责旧配置迁移、编码和本机持久化 |
| `GLMCardSettingsView` | 「··· → 卡片显示与排序…」设置视图：显隐开关、上下移动与拖放排序、恢复默认 |
| `AppDelegate` | 原生 Popover、刷新调度、重置卡操作、自启和状态聚合 |
| `GLMQuotaCycleHistory / Context / Store / Coordinator / View` | 周额度观测、连接隔离、私有保存、串行协调和原生展示，见 `17-quota-cycle-history.md` |
| `GLMOfflineRegression` | 使用临时目录和假数据的离线自检 |

七张面板内容卡片（用量进度、峰谷状态、重置卡、用量情况、每日用量、额度周期回顾、MCP 工具）均支持独立显隐与纵向排序，设置从页头「··· → 卡片显示与排序…」进入并保存在本机，可恢复默认。显隐只控制面板渲染，不影响刷新调度、历史采集与网络请求；固定更新入口和凭据恢复入口不属于可隐藏卡片，全部隐藏时面板提供经「···」恢复的入口。

`GlmUsage.swift` 保留唯一应用入口与面板组装是当前的边界约定，不是永久架构约束；`PanelCustomization.swift` 已从其中分离出卡片布局模型与设置视图。后续拆分时优先分离凭据、网络、Peak、更新和 UI。

## 3. 主要数据流

### 额度、用量与订阅

面板输入的套餐 API Key → 智谱额度接口验证 → GlmUsage 的 macOS 钥匙串条目 → 额度与用量刷新。环境变量 `GLM_API_KEY` 或旧版 ZCode 登录凭据也可进入刷新流程。

模型统计在同一刷新中合并本机 `model_usage` 的国内 Start Plan 请求。逐次请求的时间和 Token 总数用于周期汇总及日图，同名模型合并；服务端原始值加本次本机快照后进入新鲜度处理，重复刷新不会累加旧值。SQLite 只读，查询与网络回调在后台运行；无本机请求表时保留原统计，读取异常时沿用上次完整值。手动连接或环境变量提供 API Key 时只使用服务端统计。

连接来源和已保存 Key 的优先级保持不变。正常面板仅在顶部「GLM 用量」标题保留连接设置入口，底部不再展示配置按钮；明确凭据故障才显示「修复连接」。启动和轮询仅静默读取，不再自动调用交互式解锁；只有用户点击修复/设置才能请求系统授权，避免授权模态框阻塞菜单栏和刷新。普通网络失败沿用原自动重试，不自动改认证或删除连接。

凭据文件保持只读。认证信息会发送给对应智谱／ZCode 服务，不发送到开发者自有服务器，也不得写入仓库、日志或状态文件。

### 重置卡

状态查询 → 可用卡与到期时间展示 → 用户主动点击和二次确认 → 带幂等 key 的使用请求 → 额度刷新。

网络或 5xx 导致结果未知时，按卡类型保存并复用原幂等 key。预览模式禁用真实操作，任何定时刷新不得自动用卡。

### 自动更新

GitHub Release → 可安装版本选择 → ZIP / SHA256 下载 → 身份、版本、签名与离线自检 → 暂存 → 停止目标进程 → 换包 → 健康检查 → 成功清理或失败回滚。

更新器只处理当前应用路径和 `com.local.glm-usage`，不得按名称模糊终止其他进程。

## 4. 信任边界

- 智谱监控接口与 ZCode 逆向接口的稳定性不同，重置卡接口变化不得影响其他额度区块。
- OAuth token 可能过期，重置卡失败必须独立降级，不能伪造成卡数为零。
- ZCode 3.18.0 的 `enc:v2:os` 密钥由系统钥匙串管理；授权后可读取相关套餐和重置卡凭据。GlmUsage 单独保存用户在面板提交并验证通过的套餐 API Key。
- GitHub Release 与 SHA256 来自同一信任源；ad-hoc 签名不提供独立发布者身份验证。
- Peak 活动日期是带时效的配置，必须可测试并在过期后自动失效。
- 离线 mock、真实接口验证和真实安装验收是不同证据。
- 当前没有 CI 强制发布门禁，也没有完整系统版本兼容性矩阵。

面板支持纯色、经典毛玻璃和 macOS 26+ 液态玻璃，从页头「··· → 背景样式」进入；用户选择保存在本机，系统降低透明度时临时显示纯色。更新前在面板中展示说明并确认，确认时核对版本和说明未变化。
